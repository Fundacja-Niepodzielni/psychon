# H10 · Testy wiedzy + warsztat

Moduł M6. Branch `pakiet/H10-testy-warsztat`. Flaga: `config('features.h10')`.

## Co działa

### API — uczestnik
- `GET /courses/{slug}/test` — pytania jedno po drugim, **bez flag poprawności**;
  zwraca `test_id`, `pass_threshold`, `attempts_used`, `attempts_limit`, `questions[]`.
  Etap zablokowany (reguła sekwencyjna z `CourseAccess::state`) → `403 course_locked`
  z `reason.required_course_id` i `reason.missing`.
- `POST /tests/{id}/attempts` — ocenianie **wyłącznie serwerowe**:
  - numer podejścia liczony w transakcji z `lockForUpdate` (unikat
    `(user_id, test_id, attempt_number)` jest twardą barierą wyścigu),
  - zapis `questions_snapshot` — zamrożona treść pytań i odpowiedzi,
  - `score_percent = round(poprawne / wszystkie * 100)`, `passed = score >= próg`,
  - próg i limit: `Settings::edition('test_pass_threshold' / 'test_attempts_limit')`,
    z nadpisaniem per kurs w kolumnach `tests.*` (null = wartość edycji),
  - limit wyczerpany → `403 attempts_exhausted`,
  - odpowiedź spoza pytania / spoza testu → `422 validation_failed`,
  - audyt `attempt.finished` przy **każdym** ukończonym podejściu,
  - ostatnie niezaliczone podejście → `Notify::send('attempt.failed_final')` do
    wszystkich opiekunów projektu.
- `GET /tests/{id}/attempts` — historia własnych podejść (lista + `meta`,
  `meta.extra` z progiem i limitem).

### API — administracja (`project_manager` / `super_admin`)
- `GET/POST /admin/tests/{id}/questions`, `PATCH/DELETE /admin/questions/{id}` —
  bank pytań (CRUD, dokładnie jedna poprawna odpowiedź). Edycja/usunięcie **nie
  zmienia historii** — podejścia trzymają własny snapshot. Rejestr audytu §3.2 nie
  ma sluga dla banku pytań, więc te operacje nie są audytowane (świadomie).
- `POST /admin/workshop/{userId}/complete` — odznaczenie warsztatu, idempotentne,
  audyt `workshop.completed`; zasila warunek certyfikatu `workshop` przez
  `ProgressAggregator`.
- `POST /admin/tests/{testId}/users/{userId}/reset-attempts {reason}` — reset
  limitu (powód obowiązkowy, brak → `422`); czyści podejścia użytkownika do tego
  testu, numeracja startuje od 1; audyt `attempts.reset` (kto, komu, powód).

### Ekran uczestnika
`#/panel/kursy/:slug/test` (`app/(uczestnik)/panel/kursy/[slug]/test/page.tsx`):
intro z progiem i liczbą podejść → pytania **pojedynczo, bez cofania** → ekran
wyniku (procent, próg, badge zaliczenia, lista błędnych pytań) → historia podejść.
Ekran blokady dla `course_locked`, komunikat po wyczerpaniu podejść.

## Jak pokazać

```bash
# środowisko
bash scripts/setup.sh && (cd frontend && npm run dev)

# happy path na seedzie (marta ma zdany test 1, oblany test 2 — 1/3 podejść)
# 1. zaloguj marta@demo.pl / demo1234, wejdź w kurs 2 „Wywiad psychologiczny" → Test
# 2. rozwiąż ≥ 80% → ekran „Zaliczony", kolejny etap odblokowany (dzwonek H05)
# 3. rozwiąż < 80% dwukrotnie → po 3. podejściu blokada + powiadomienie u opiekun@demo.pl

# reset limitu (opiekun@demo.pl / admin1234)
curl -X POST .../api/v1/admin/tests/2/users/<marta_id>/reset-attempts \
  -H 'Authorization: Bearer <token>' -d '{"reason":"Problem techniczny w 3. podejściu"}'

# warsztat → warunek certyfikatu
curl -X POST .../api/v1/admin/workshop/<marta_id>/complete -H 'Authorization: Bearer <token>'
```

## Czego brakuje / decyzje

- **Panel banku pytań (UI)** — API + testy gotowe; ekran edycji pytań należy do
  slotu w `#/admin/kursy` (właściciel strony: H08a). Do dołożenia po H08a.
- `GET /tests/{id}/attempts` wystawia **tylko własną** historię uczestnika; wgląd
  administracji w cudzą historię idzie przez kartę osoby (H18).
- Reset limitu **kasuje** dotychczasowe podejścia (numeracja od 1). Model danych
  jest zamrożony i nie ma kolumny na „bonusowe podejścia", więc to najprostsze
  spójne rozwiązanie; ślad po resecie zostaje w dzienniku działań.
- Powiadomienie `attempt.failed_final` trafia do wszystkich kont `project_manager`.
