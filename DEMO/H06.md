Konta i dane pochodzą z `backend/database/seeders/DemoSeeder.php`. Nie używamy
prawdziwych danych osobowych.

## Integracja ze stroną kursu H05

Właściciel H05 importuje komponent w swoim slocie i przekazuje wyłącznie
identyfikator lekcji:

    import LessonPlayer from "@/components/lesson/LessonPlayer";

    <LessonPlayer lessonId={8} />;

H06 nie zmienia strony kursu, layoutu ani menu. Pozycja filmu nie jest zapisywana
na serwerze; po ponownym otwarciu odtwarzacz zaczyna od początku. Liczniki
`watched_seconds` i `active_seconds` pozostają trwałe.

## Scenariusz demonstracyjny

1. Zaloguj się jako Marta i otwórz stronę kursu zawierającą `LessonPlayer`.
2. Potwierdź stan ładowania, tytuł lekcji i atrapę odtwarzacza. Uruchom odtwarzanie.
3. Poczekaj na heartbeat (odtwarzacz wysyła go co 10 sekund). Stan „Zapisywanie postępu” powinien zniknąć po odpowiedzi API, a pasek postępu się zaktualizować.
4. Podczas odtwarzania przełącz kartę w tło na co najmniej jeden heartbeat. Po powrocie sprawdź, że `active_seconds` nie zwiększył się za czas niewidocznej karty.
5. Otwórz tę samą lekcję w dwóch kartach i pozwól obu wysłać heartbeat w tym samym oknie. Serwer nie powinien naliczyć więcej niż 35 sekund aktywności z nakładających się żądań.
6. Zatrzymaj API lub odłącz sieć przed kolejnym heartbeatem. Komponent pokazuje błąd zapisu i przycisk „Spróbuj ponownie”, zachowując niezapisany przyrost.
7. Przywróć API i wybierz „Spróbuj ponownie”. Przyrost powinien zostać wysłany, a komunikat błędu zniknąć.
8. Dla lekcji z aktywnym czasem poniżej progu kliknięcie ukończenia zwraca błąd `not_enough_active_time`; lekcja nie zostaje oznaczona jako ukończona.
9. Po osiągnięciu progu przycisk „Ukończ lekcję” staje się dostępny. Kliknięcie zwraca `is_completed: true`, pokazuje polski komunikat sukcesu i zachowuje `completed_at` przy kolejnym kliknięciu.
10. Po ponownym otwarciu lekcji potwierdź, że liczniki są zachowane, ale odtwarzacz startuje od początku (brak pola pozycji w zamrożonym schemacie).

## Szybka weryfikacja API

Po uzyskaniu tokenu przez `POST /api/v1/auth/login`:

    curl -H "Accept: application/json" \
      -H "Authorization: Bearer $TOKEN" \
      http://localhost:8000/api/v1/lessons/8

    curl -X POST -H "Accept: application/json" \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer $TOKEN" \
      -d '{"watched_delta":10,"active_delta":10}' \
      http://localhost:8000/api/v1/lessons/8/progress

    curl -X POST -H "Accept: application/json" \
      -H "Authorization: Bearer $TOKEN" \
      http://localhost:8000/api/v1/lessons/8/complete

Oczekiwane błędy to: 401 `unauthenticated`, 403 `access_expired` lub
`course_locked`, 422 `validation_failed` dla niepoprawnego heartbeat oraz 422
`not_enough_active_time` przed progiem.
