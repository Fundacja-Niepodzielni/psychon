## Co działa

**Backend:**

| Plik | Rola |
|---|---|
| `app/Services/H20/ReportSummary.php` | raport edycji — `summary` (przyjęte/aktywne/ukończone, suma+średnia godzin, konsultacje, certyfikaty) + `people` (zestawienie imienne), jedno źródło dla ekranu, CSV i testów |
| `app/Queries/AdminAuditQuery.php` | filtry dziennika (`action`, `user_id` = aktor, `from`/`to`), wspólne dla listy i CSV |
| `app/Http/Requests/H20/AuditIndexRequest.php` | `action` ograniczony do rejestru kontraktu §3.2 (`Rule::in`) |
| `app/Http/Resources/AuditLogEntryResource.php` | wiersz JSON + `toCsvRow()` — ten sam zestaw pól |
| `app/Http/Controllers/Api/V1/Admin/{ReportController,AuditController}.php` | trasy poniżej |

| Metoda | Trasa | Zachowanie |
|---|---|---|
| `GET` | `/api/v1/admin/report` | `{data:{summary:{...}, people:[...]}}` |
| `GET` | `/api/v1/admin/report/export.csv` | CSV zestawienia imiennego, wspólny helper `Csv` (BOM+`;`) |
| `GET` | `/api/v1/admin/audit` | lista wpisów dziennika, paginacja, filtry `action`/`user_id`/`from`/`to` |
| `GET` | `/api/v1/admin/audit/export.csv` | CSV dziennika, te same filtry, wspólny helper `Csv` |

Wszystkie cztery: `role:project_manager,super_admin`. **Zero tras modyfikacji audytu** —
`h20.php` nie rejestruje żadnego `PATCH`/`PUT`/`DELETE` pod `/admin/audit/*`, więc próba
zwraca naturalne 404 Laravela (nie ma czego przechwycić).

- **`active`/`completed`/`certificates_issued` wołają wprost `App\Services\H19\DashboardSummary::build()`**
  (pulpit, H19) zamiast liczyć te same `COUNT`-y drugi raz — gwarancja równości z kryterium ★1
  przez wspólny kod, nie przez „policzone tak samo". `hours_accepted`/`consultations` per osoba
  używają tych samych kolumn co `ProgressAggregator` (`internship_entries.hours` /
  `.consultations_count`, status `accepted`).
- `user_id` w filtrze dziennika = **aktor** (kto wykonał akcję, `audit_log.actor_id`) — kontrakt
  nie precyzuje, który koniec relacji; „dziennik działań" (kto co zrobił) czyni to najbardziej
  naturalną interpretacją, udokumentowaną w `design.md` tej zmiany OpenSpec.

## Jak pokazać (scenariusz ręczny)

Wymagane: `docker compose up -d --wait`, `cd frontend && npm run dev`.

1. **Backend, w izolacji:** `docker compose exec app php artisan test --filter=H20` → 15 passed.
2. **Front — raport:** zaloguj się jako `admin@demo.pl` / `admin1234` → menu **Raport**
   (`/admin/raport`) → kafelki: aktywne 3, ukończone 1, certyfikaty 1, suma godzin 113,5,
   konsultacje 101; tabela imienna z Martą (41,5h / 37 konsultacji) i Olą (72h / 64,
   certyfikat „Wydany"). **Drukuj** → podgląd wydruku (przyciski/filtry znikają, widoczny
   nagłówek raportu).
3. **Front — dziennik:** menu **Dziennik działań** (`/admin/dziennik`) → filtr „Zdarzenie" =
   „Przedłużono dostęp" → tylko wpisy `access.extended`; zakres dat zawęża listę.
4. **API wprost — brak tras modyfikacji:** `PATCH /api/v1/admin/audit/1` jako super_admin →
   `404 not_found`.
5. **Izolacja ról:** zaloguj się jako `marta@demo.pl` → ręczne wejście na `/admin/raport` →
   ekran 403 (strażnik roli z H02).

## ⚠️ Cudze pliki — jedna wymuszona poprawka

`tests/Feature/PermissionMatrix/PermissionMatrixTest.php` (H02, `DONE`, scalone PR #8)
zawierał wiersz `['POST', '/api/v1/admin/audit']` w `matrix_5f`, zakładający że **żadna**
trasa `/admin/audit` nie istnieje. Odkąd H20 rejestruje `GET /admin/audit`, ten sam `POST`
trafia w 405 (zła metoda na istniejącej trasie), nie 404 (brak trasy) — test zaczął czerwienić
się z powodu mojej, kontraktowo poprawnej zmiany. Naprawiłem wiersz na `/admin/audit/1`
(podścieżka bez żadnej zarejestrowanej metody, więc naprawdę 404), zgodnie z tym samym
rozróżnieniem, którego użyłem we własnym `AuditTest::test_no_audit_mutation_routes_exist`.
Jednolinijkowa, mechaniczna poprawka — bez niej `php artisan test` (pełny pakiet) jest czerwony
dla każdego, kto zbuduje na tym branchu.

## Czego brakuje / świadome decyzje

- **„Osoby przyjęte" liczone z `applications.status = accepted`** — w danych demo wynosi 0
  (konta demo są tworzone bezpośrednio przez seeder, nie przez realny przepływ akceptacji
  zgłoszenia H03). Nie jest to błąd — `04-seed-demo.md` §5 nie definiuje wiążącej wartości dla
  tego licznika, w przeciwieństwie do `active`/`completed`/`certificates_issued`/godzin/konsultacji.
- **„Średnia godzin" = suma / liczba osób aktywnych** — kontrakt nie precyzuje mianownika;
  wybrana definicja jest udokumentowana (i uzasadniona) w `design.md` tej zmiany OpenSpec.
- **`user_id` w filtrze dziennika = aktor, nie podmiot** — jak wyżej, zapisane w `design.md`
  jako świadoma decyzja przy niejednoznacznym kontrakcie.
- **Brak testów frontendu** — jak w poprzednich pakietach; ekrany zweryfikowane `npm run build`
  + ręcznym scenariuszem i sprawdzeniem API na żywo (curl, w tym BOM/nagłówki CSV bajt po
  bajcie).
- **Print CSS** — wyłącznie warianty `print:` z Tailwind 4 (wbudowane, zero nowych zależności);
  brak wcześniejszego wzorca w repo, więc to pierwsze użycie tego mechanizmu w projekcie.
