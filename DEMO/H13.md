# H13 · Certyfikaty + weryfikacja publiczna

Moduł M10. Branch `pakiet/H13-certyfikaty`. Flaga: `config('features.h13')`.
Zaplanowane i wdrożone przez OpenSpec — `openspec/changes/h13-certyfikaty-weryfikacja/`.

## Co działa

### ★ Minimum P0 — warunki ukończenia
- `GET /certificate/conditions` → `{"data":{"eligible":bool,"conditions":[…]}}` — cztery
  filary (`courses`, `internship`, `supervision`, `workshop`) liczone przez
  `App\Support\H13\CertificateConditions` **wyłącznie z `ProgressAggregator::for()`**
  i progów `Settings::edition(...)`. Godziny jako łańcuchy (`"41.5"` / `"72"`), warunek
  `workshop` bez liczników. Dostęp: tylko `volunteer` (`access.active`); student /
  prowadzący → 403, gość → 401.
- Ekran `#/panel/certyfikat` — lista warunków z paskami postępu i statusem, przycisk
  „Wygeneruj certyfikat" aktywny tylko przy `eligible`; wpis w rejestrze menu uczestnika.

### Pełny zakres
- `POST /certificate/generate` — przy brakach `422 conditions_not_met` z
  `reason.missing`; przy komplecie `202 {"data":{"status":"queued"}}` + zadanie
  `GenerateCertificate` (kolejka `sync` w testach).
- Zadanie w tle w jednej transakcji: blokada wierszy certyfikatów edycji
  (`lockForUpdate`), numer **ciągły per edycja** `NP/<rok>/<3 cyfry>` (kontynuuje po
  seedowym `NP/2026/001` oli), idempotencja pary `(user_id, edition_id)`, snapshot
  warunków, losowy unikalny `verification_token`, `users.program_completed_at` (gdy
  puste), audyt **`certificate.issued`**. Render pliku (`PdfService` — stub HTML) po
  commit; powiadomienie `certificate.ready`.
- `GET /certificate/download` — plik wydanego certyfikatu właściciela; brak wydania → 404.
- Publiczne (bez auth, bez `access.active` — już na liście `config/public_routes.php`):
  - `GET /verify/{number}` → `{"data":{"number","status","edition","issued_at"}}`
    (`status`: `valid | revoked`). Numer nieznany **oraz** w błędnym formacie → jeden
    `404` z komunikatem „Nie znaleziono certyfikatu o podanym numerze." (bez ujawniania
    formatu — trasa bez `where` na parametrze).
  - `GET /verify/qr/{token}` → ten sam payload; token nieznany → identyczny `404`.
- Ekrany publiczne: `#/weryfikacja` (wyszukiwarka numeru) i `#/certyfikat`
  (wejście z QR: `?token=` / `?number=`).

## Jak pokazać

```bash
bash scripts/setup.sh && (cd frontend && npm run dev)

# ★ warunki — marta (niespełnione) i ola (komplet)
# zaloguj marta@demo.pl / demo1234 → #/panel/certyfikat → 1/10 · 41,5/72 · 5/6 · warsztat NIE, przycisk nieaktywny
# zaloguj ola@demo.pl  / demo1234 → #/panel/certyfikat → wszystkie warunki spełnione

# publiczna weryfikacja (bez logowania)
# otwórz http://localhost:3001/weryfikacja → wpisz NP/2026/001 → „Ważny", edycja 2026
# losowy ciąg → „Nie znaleziono certyfikatu o podanym numerze."

# QR: w wygenerowanym pliku certyfikatu jest adres #/certyfikat?token=<token> prowadzący do tej samej weryfikacji
```

## Testy wspólne (handshake — wynik do obu `DEMO/HXX.md`)

- **Bezterminowy dostęp (H13 + H04):** `GenerateCertificateTest::test_issuing_lifts_the_time_boxed_access_gate`
  pokazuje, że po wydaniu `program_completed_at` zdejmuje bramkę `access.active`.
  Domknięcie po stronie H04 (lista wyjątków + zadanie cykliczne) — do potwierdzenia
  z właścicielem H04.
- **Zgodność liczb (H13 + H18 + H19 + H20):** `CertificateConditionsTest::test_condition_numbers_equal_the_progress_aggregator`
  potwierdza, że warunki liczą się z tego samego `ProgressAggregator` co karta osoby,
  pulpit i raport. Do sprawdzenia z właścicielami H18/H19 przy integracji.

## Czego brakuje / decyzje

- **Kod QR w pliku certyfikatu** — teraz w widoku jest czytelny adres weryfikacji +
  placeholder QR. Realny, skanowalny QR domykamy razem z podmianą `PdfService` na
  właściwy renderer PDF po hackathonie (design `D4`, open question — czeka na zgodę
  sztabu na wniesienie enkodera QR jako kod pakietu, zasada „zero nowych zależności").
- **Unieważnianie certyfikatów** — poza hackathonem (kontrakt §4). `status` w
  odpowiedzi weryfikacji już obsługuje `revoked` (testowane przez ustawienie
  `revoked_at`), ale trasy unieważniania nie powstają.
- **Seeder pakietu (zadanie 7.4)** — stan `oli` z `DemoSeeder` (certyfikat `NP/2026/001`,
  `program_completed_at`, warsztat, 72 h, 6 obecności) wystarcza do demo warunków i
  weryfikacji publicznej. Osobny seeder H13 nie jest potrzebny; do potwierdzenia ze
  strażnikiem schematu przy integracji (zakresy ID per pakiet).
- `GET /tests/...`/wgląd administracji w cudzy certyfikat — poza zakresem H13 (karta
  osoby to H18).
