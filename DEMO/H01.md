## Co działa

**Backend — `routes/api/h01.php` (flaga `features.h01`):**

| Metoda | Trasa | Zachowanie |
|---|---|---|
| `GET` | `/api/v1/me` | pełny profil; właściciel widzi swój PESEL w całości; dołączona lista zgód (`type`, `document_version`, `granted_at`, `status`) |
| `PATCH` | `/api/v1/me` | `first_name`, `last_name`, `phone`, `pesel`, `address.{street,city,zip}`; pole `email` usuwane przed walidacją (nie zmienia adresu) |
| `POST` | `/api/v1/me/exports` | `202` `{ "data": { "id": "ex_…", "status": "queued" } }`; zleca zadanie w tle |
| `GET` | `/api/v1/me/exports/{id}` | status eksportu; cudzy `id` → `404 not_found` |
| `GET` | `/api/v1/me/exports/{id}/download` | plik JSON (`attachment; filename=moje-dane-ex_….json`); cudzy `id` → `404` |

- **Walidacja PESEL** (`app/Rules/Pesel.php`): 11 cyfr + poprawna data urodzenia (miesiąc koduje stulecie) + cyfra kontrolna. Komunikat „Nieprawidłowy numer PESEL." przy polu (`error.errors.pesel`).
- **Szyfrowanie:** `pesel` oraz `address_*` — `encrypted` w castach modelu `User` (starter). PESEL jest też w `$hidden` — ujawniany wyłącznie jawnie przez `ProfileResource` dla właściciela.
- **Eksport w tle** (`app/Jobs/GenerateDataExport.php`): pięć zakresów — profil, zgody, postępy (`ProgressAggregator` + per-lekcja), wpisy stażu, metadane dokumentów (bez plików PDF). Plik na dysku `local` w `exports/`. Po sukcesie: `Notify::send('export.ready', …, link: /panel/profil)`.
- Kolejka: driver `database`, przetwarza kontener `queue` (w testach `sync`).

**Frontend — `/panel/profil` (`app/(uczestnik)/panel/profil/page.tsx`):**

- Formularz „Dane osobowe": imię, nazwisko, e-mail (tylko do odczytu, wyszarzony, z podpowiedzią), telefon, PESEL, adres. Błędy 422 mapowane na pola (w tym `address.street` itd.). Pola krótkie (telefon, PESEL, kod pocztowy) zawężone do sensownej szerokości.
- Karta „Zgody": lista z wersją, datą i statusem (badge „Udzielona" / „Wycofana").
- Karta „Eksport danych (RODO)": przycisk zlecający eksport → polling statusu co 2 s → „Pobierz plik" (fetch z tokenem Bearer → blob → zapis). Stan błędu obsłużony.
- Tylko komponenty z `components/ui/*` i tokeny; brak własnych stylów ad hoc.

## Jak pokazać (scenariusz ręczny)

Wymagane: `docker compose up -d --wait`, `cd frontend && npm run dev`.

1. **Logowanie** — http://localhost:3000/logowanie → `marta@demo.pl` / `demo1234`.
2. Menu boczne → **Profil** (`/panel/profil`).
3. **Edycja danych:** zmień telefon, kliknij **Zapisz zmiany** → zielony komunikat „Zapisano zmiany.". Odśwież stronę — wartość się utrzymuje.
4. **E-mail tylko do odczytu:** pole e-mail jest wyszarzone, nie da się go edytować.
5. **Walidacja PESEL:** wpisz `12345678901` → **Zapisz** → czerwony błąd „Nieprawidłowy numer PESEL." pod polem. Wpisz poprawny (seed Marty: `90010112301`) → zapisuje się.
6. **Zgody:** karta „Zgody" pokazuje `regulamin` i `polityka` z datą i badge „Udzielona".
7. **Eksport RODO:** karta „Eksport danych" → **Przygotuj eksport danych**. Badge przechodzi „Przygotowywanie…" → „Gotowy" (kontener `queue` przetwarza w ~2 s). **Pobierz plik** → `moje-dane-ex_….json` z sekcjami `profile`, `consents`, `progress`, `internship_entries`, `documents`.
8. **Powiadomienie:** Mailpit http://localhost:8025 — wiadomość `export.ready` (symulowana, nie wychodzi na zewnątrz).
9. **Izolacja (opcjonalnie, API):** zaloguj się jako `ola@demo.pl`, spróbuj `GET /api/v1/me/exports/{id Marty}` → `404 not_found`.

## Czego brakuje / świadome decyzje

- **Edytowalność imienia i nazwiska** — zakres H01 wymienia jawnie tylko telefon/adres/PESEL, a jako „tylko do odczytu" tylko e-mail. Zrobione jako **edytowalne** (za M2 pkt 3). Do potwierdzenia z makietą / strażnikiem kontraktu.
- **Brak wpisu audytowego dla eksportu** — `export.*` nie występuje w rejestrze audytu §3.2, a §3.2 jest jedynym źródłem prawdy. Zgodnie z kontraktem eksport nie loguje audytu.
- **`consents` w odpowiedzi `GET /me`** — dodane do koperty (przykład w kontrakcie używa `…`, więc ilustracyjny). Potrzebne dla karty „Zgody".
- **Zgodność z makietą (kolory)** — CTA / logo / aktywny link w sidebarze różnią się od makiety (starter spłaszczył fiolet do zieleni, część dla kontrastu WCAG). To pliki współdzielone (`globals.css`, `Button.tsx`, `PanelShell.tsx`) — decyzja design systemu, poza H01.
- **Brak testów frontendu** — repo nie ma runnera JS; ekran pokryty `npm run build` + scenariuszem ręcznym powyżej.
- **Nazewnictwo gałęzi** — użyto `feature/h01-profile-export`; konwencja zespołu (`openspec/changes/koordynacja-pakietow-h01-h21`) to `pakiet/H01-nazwa`.
