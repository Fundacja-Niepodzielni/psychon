zamrożony w `2026_01_01_000040_create_courses_tables.php`).

## Ustalenia kontraktowe (K1–K12)

**Status: NIEZATWIERDZONE.** Kontrakt `docs/hackathon/02-kontrakt-api.md` nie ma
sekcji §2 dla H09. Zgłoszenie K1–K12 z proponowanymi odpowiedziami jest w
`DEMO/H9-prep-doc.md` §6 i idzie do strażnika kontraktu **przed** złączeniem PR
(przewodnik §4 pkt 2). Implementacja rusza równolegle na **proponowanych**
odpowiedziach; rozjazdy naprawiamy przed PR. Ta sekcja zbiera wybory przyjęte w
kodzie — do potwierdzenia dosłownego przez strażnika:

- **K1** — odpięcie: `DELETE /admin/courses/{course}/assignments` z
  `assignment_id` w ciele (kształt z karty pakietu), odpowiedź `200` z zasobem
  przypisania (z ustawionym `unassigned_at`). Odpięcie = `unassigned_at = now()`,
  nigdy `DELETE` wiersza.
- **K2** — pełna lista tras jak w tabeli wyżej. `GET`/`PATCH /me/instructor-profile`
  jako nowe podścieżki `/me` (kontrakt §1 traktuje `/me` jako wyjątek zastany —
  wymaga zgody strażnika; alternatywa `/instructor-profile`).
- **K3** — payload przypisania: `{instructor_id, lesson_id?}`; `lesson_id` puste
  lub brak = przypisanie całego kursu; odpowiedź `201` z zasobem przypisania
  (`id, course_id, lesson_id, instructor{id,first_name,last_name}, assigned_by,
  assigned_at, unassigned_at`).
- **K4** — DTO wizytówki: `{id, user_id, first_name, last_name, city,
  specializations[], bio, experience, responsibilities[], courses[{id, slug,
  title, sequence_order}]}`; `GET /instructors/{id}` dodatkowo
  `supervisor: {id, name} | null`. **`id` = id użytkownika prowadzącego**
  (spójne z `data.instructor.id` w `GET /courses/{slug}` i `assignment.instructor.id`),
  `user_id` powtórzone jawnie.
- **K5** — jedno aktywne przypisanie na parę `(course_id, lesson_id)`. Drugie →
  `422 conditions_not_met` z `reason.assignment_id`. (Alternatywa „auto-odpięcie
  poprzednika" odrzucona — administracja najpierw odpina, potem przypisuje.)
- **K6** — `instructor_id` musi wskazywać konto z rolą `instructor`; inaczej
  `422 validation_failed`.
- **K7** — edycja własnej wizytówki **nie jest audytowana** (rejestr §3.2 daje
  H09 tylko `assignment.created` / `assignment.removed`; wizytówka nie jest daną
  wrażliwą). Jeśli strażnik zażąda audytu — mapowanie na istniejący slug z
  `details.op`.
- **K8** — reguła dziedziczenia jako kod: `AssignmentResolver::forLesson(Lesson): ?User`
  jest jedynym źródłem; H17 konsumuje, nie reimplementuje (analogia do
  `CourseAccess`). Wykładnia przyjęta: „nowe pytania do nowej osoby" znaczy
  **pytania bez odpowiedzi** — granicą jest fakt odpowiedzi (`answered_by`),
  nie data zadania (jedyne wykonalne bez migracji: `instructor_questions` nie ma
  kolumny `instructor_id`). Ostateczny kształt handshake'u ustala się z H17.
- **K9** — `GET /instructors` **nie jest publiczne**; nic nie dopisano do
  `config/public_routes.php`. Trasa za `auth:sanctum` + `access.active`.
- **K10** — cała lista wizytówek dla każdej zalogowanej roli; PESEL/adres/e-mail
  **nie wchodzą** do DTO.
- **K11** — paginacja `?page&per_page` (domyślnie 25, max 100), koperta
  `{data, meta}` (`current_page`, `per_page`, `total`, `last_page`).
- **K12** — adresat powiadomień `assignment.created` / `assignment.removed` =
  prowadzący, którego dotyczy zmiana; link `/panel/prowadzacy`. `Notify::send`
  tworzy równocześnie wiersz `emails` o statusie `simulated`.

## Przejście demo

Komendy backendu przez docker. Konta i hasła: `docs/hackathon/04-seed-demo.md` §2.

**0. Czysty stan**

```bash
docker compose down -v && bash scripts/setup.sh
```

**1. Wizytówki (dla każdej zalogowanej roli)**

```bash
curl -H "Authorization: Bearer <token marty>" http://localhost:8000/api/v1/instructors
# → 200 { "data": [ { "id": <joanna>, "first_name": "Joanna", "city": "Warszawa",
#         "specializations": ["interwencja kryzysowa","praca z młodzieżą"],
#         "courses": [ {slug: "podstawy-pomocy"}, {slug: "wywiad-psychologiczny"},
#                      {slug: "interwencja-kryzysowa"} ] } ], "meta": { ... } }

curl -H "Authorization: Bearer <token marty>" http://localhost:8000/api/v1/instructors/<joanna>
# → 200, dodatkowo "supervisor": null  (Joanna nie ma ustawionego supervisor_id)
```

Brak nagłówka `Authorization` → `401`. DTO nie zawiera `email`, `pesel`, `address`.

**2. Własna wizytówka prowadzącego**

Zaloguj się jako `joanna@demo.pl`.

```bash
curl -H "Authorization: Bearer <token joanny>" http://localhost:8000/api/v1/me/instructor-profile
# → 200, jej dane + "courses" 1–3

curl -X PATCH -H "Authorization: Bearer <token joanny>" -H "Content-Type: application/json" \
  -d '{"city":"Gdańsk","specializations":["praca z traumą"]}' \
  http://localhost:8000/api/v1/me/instructor-profile
# → 200 z zaktualizowaną wizytówką

curl -H "Authorization: Bearer <token joanny>" http://localhost:8000/api/v1/instructor/courses
# → 200 { "data": [ {slug:"podstawy-pomocy"}, {slug:"wywiad-psychologiczny"}, {slug:"interwencja-kryzysowa"} ] }
```

`marta@demo.pl` na `/me/instructor-profile` → `403 forbidden`.

**3. Przypisania — kryterium 2 (★): audyt + powiadomienie**

Zaloguj się jako `admin@demo.pl` (`admin1234`).

```bash
# odczyt
curl -H "Authorization: Bearer <token admina>" \
  http://localhost:8000/api/v1/admin/courses/<kurs 4 „praca-z-emocjami">/assignments
# → 200 { "data": [] }  (kurs 4 nie ma prowadzącego)

# założenie przypisania kursowego
curl -X POST -H "Authorization: Bearer <token admina>" -H "Content-Type: application/json" \
  -d '{"instructor_id":<joanna>}' \
  http://localhost:8000/api/v1/admin/courses/<kurs 4>/assignments
# → 201 z zasobem przypisania (lesson_id: null)
# → w audycie (`audit_log`) wpis `assignment.created`
# → w `notifications` wiersz `assignment.created` dla Joanny + `emails` status `simulated`

# drugie przypisanie tej samej pary → odrzucone
curl -X POST ... -d '{"instructor_id":<inny prowadzący>}' .../<kurs 4>/assignments
# → 422 { "error": { "code": "conditions_not_met", "reason": { "assignment_id": <id> } } }

# odpięcie
curl -X DELETE -H "Authorization: Bearer <token admina>" -H "Content-Type: application/json" \
  -d '{"assignment_id":<id>}' \
  http://localhost:8000/api/v1/admin/courses/<kurs 4>/assignments
# → 200; wiersz `course_assignments` nadal istnieje z ustawionym `unassigned_at`
# → audyt `assignment.removed` + powiadomienie `assignment.removed`

# ponowne odpięcie tego samego → 404, bez dodatkowego audytu i powiadomienia
```

`instructor_id` bez roli `instructor` → `422 validation_failed`.
`lesson_id` z innego kursu → `422 validation_failed`.
`marta`/`filip`/`joanna` na trasach `admin/courses/.../assignments` → `403 forbidden`.

**4. Reguła dziedziczenia — kryterium 1 (★)**

## Znane ograniczenia

- **Kontrakt K1–K12 niezatwierdzony.** Zgłoszenie do strażnika przed złączeniem
  PR. Kod trzyma się proponowanych odpowiedzi z `DEMO/H9-prep-doc.md` §6; przy
  rozjeździe poprawiamy `FormRequest`/`Resource`/scenariusze i dopisujemy
  dosłowne odpowiedzi do sekcji „Ustalenia kontraktowe" wyżej.
- **Frontend odłożony.** Ta runda to backend. Wizytówka w widoku kursu
  (`course-page.ts` ma gotowy region `"instructor"` w `main`) nie czeka na nic;
  `<AssignmentPanel>` w `#/admin/kursy` czeka na merge H08a
  (`lib/slots/admin-courses.ts`). Obie połówki to „jeden plik + dwie linie
  rejestru" — patrz `DEMO/H9-prep-doc.md` §2.4 i §3.1.
- **Kryterium 3 — test wspólny z H17 niekompletny.** H17 nie jest
  zaimplementowany. H09 dostarcza `AssignmentResolver` i pokrywa go testami
  (adresat liczony w chwili odczytu; `answered_by` zachowuje historię). Pełny
  test „nowe pytanie po zmianie prowadzącego trafia do nowej osoby" napisze H17,
  wołając `AssignmentResolver::forLesson`. Handshake zgłoszony jako K8.
- **`GET /instructors/{id}` przyjmuje id użytkownika, nie id wiersza
  `instructor_profiles`.** Świadome — reszta systemu identyfikuje prowadzącego
  po `users.id`. `data.id == data.user_id` w DTO. Do potwierdzenia jako K4.
- **Brak indeksu unikalnego** na aktywnym przypisaniu (migracje zamrożone).
  Niezmiennik „jedno aktywne na parę" jest egzekwowany w aplikacji;
  `AssignmentResolver` ma deterministyczny tie-break `orderBy('id')` na wypadek
  danych historycznych.
- **`instructor_profiles.supervisor_id`** (własny superwizor prowadzącego) jest
  prezentowany do odczytu w `GET /instructors/{id}` i `/me/instructor-profile`,
  ale **nie ma trasy do jego ustawiania** — brak jej w kontrakcie i w karcie
  pakietu. To inny „superwizor" niż `supervisor.assigned` z §3.2 (własność
  H12/H18) — H09 go nie emituje i nie dotyka `supervisor_assignments`.
