# H15 · Profil psychologa

Moduł M12. Branch `pakiet/H15-profil-psychologa`. Flaga: `config('features.h15')`.
Zaplanowane i wdrożone przez OpenSpec — `openspec/changes/h15-profil-psychologa/`.

## Co działa

### ★1 — Kwalifikowalność i weryfikacja absolwenta
- `GET/PATCH /psychologist-profile` — dostępny zawsze do odczytu; `eligible` liczone
  z `users.program_completed_at`. Wolontariusz w trakcie programu widzi
  `eligible=false` bez błędu (ekran „czego brakuje"); każda akcja zapisu (`PATCH`,
  `submit`, `documents`) dla takiego konta zwraca `403 profile_not_eligible`.
- `POST /psychologist-profile/submit` — komplet danych (specjalizacje, nurt, miasto,
  dyplom, zgoda na publikację) wymagany; braki → `422 profile_incomplete` z
  `reason.missing`. `ola@demo.pl` (seed absolwentki) może złożyć wniosek po dodaniu
  dyplomu.
- `POST /psychologist-profile/documents` (multipart) — załączniki `dyplom`,
  `niekaralnosc`, `inne`; przyjmowane tylko w stanie `draft`/`returned`.

### ★2 — Wgląd administracji w załączniki
- `GET /admin/profiles/{id}/documents/{docId}` (trasa `signed`) — każde udane
  pobranie zapisuje dokładnie jeden wpis w `sensitive_access_log`
  (`viewer_id`, `file_type=profile_document`, `file_id`, `viewed_at`) **oraz** wpis
  audytu `sensitive.viewed` (rejestr §3.2, slug już przypisany H03/H15) przez
  `AuditLog::record` — odkryte podczas implementacji, dopisane do
  `spec.md`/`tasks.md`. Link bez podpisu → `403`.

### Pełny zakres
- `GET /admin/profiles` — domyślnie wyłącznie `submitted`, sortowane po
  `created_at` rosnąco; `?status=` dla innych stanów (w tym `withdrawn`).
- `GET /admin/profiles/{id}` — pełny wniosek + lista załączników, każdy z
  podpisanym, wygasającym `download_url` (wzorzec H14).
- `POST /admin/profiles/{id}/accept` i `POST /admin/profiles/{id}/return {reason}` —
  strażnik statusu (`404 not_found` / `403 entry_locked`), audyt
  `profile.accepted`/`profile.returned`, powiadomienie tego samego typu (wzorzec H11).
  Odesłanie z powodem odblokowuje edycję i zachowuje `return_reason` do czasu
  ponownego złożenia.
- `POST /psychologist-profile/consent/withdraw` — wycofuje aktywną zgodę
  (`consents.withdrawn_at`), przenosi wniosek do stanu `withdrawn`. Widoczność dla
  zespołu: `GET /admin/profiles?status=withdrawn` (patrz „Czego brakuje" —
  `profile.withdrawn`).
- Ekrany: `#/panel/profil-psychologa` (formularz, upload załączników, złożenie,
  wycofanie zgody) i `#/admin/profile` (kolejka + `#/admin/profile/{id}` ze
  szczegółami, pobraniem załączników i decyzją).

## Jak pokazać

```bash
bash scripts/setup.sh && (cd frontend && npm run dev)

# wolontariusz w trakcie programu — ekran wyjaśniający
# zaloguj marta@demo.pl / demo1234 → #/panel/profil-psychologa
#   → informacja, że wniosek będzie dostępny po ukończeniu programu

# ola@demo.pl / demo1234 — absolwentka, profil draft gotowy do złożenia
# zaloguj ola@demo.pl / demo1234 → #/panel/profil-psychologa
#   → uzupełnione dane, dodaj załącznik typu „Dyplom", zaznacz zgodę na publikację
#   → „Złóż wniosek" → status „Oczekuje na weryfikację"

# decyzja administracji
# zaloguj opiekun@demo.pl / admin1234 → #/admin/profile
#   → wniosek Oli w kolejce → szczegóły → „Pobierz" przy załączniku (loguje wgląd)
#   → „Akceptuj wniosek" albo odeślij z powodem

# wycofanie zgody (jako ola, po decyzji)
# #/panel/profil-psychologa → „Wycofaj zgodę” → status „Zgoda wycofana”
#   → w #/admin/profile?status=withdrawn wniosek jest nadal widoczny
```

## Czego brakuje / decyzje

- **Status `published`** — poza zakresem tego pakietu (decyzja użytkownika); publikacja
  pozostaje ręczną operacją zespołu poza API na czas hackathonu.
- **Szyfrowanie załączników at-rest** — MVP korzysta z tego samego lokalnego dysku co
  H14 (`Storage::disk('local')`), bez warstwy szyfrowania; świadome uproszczenie
  hackathonowe, do potwierdzenia przez sztab (`design.md` → Open Questions).
- **Slug `profile.withdrawn`** — zgłoszenie do strażnika kontraktu:
  [PR #23](https://github.com/tomekwilczak/psychon-hackaton/pull/23), status: oczekuje
  na review w chwili zamknięcia tego pakietu. Do czasu przyznania slugu wycofanie
  zgody i tak ustawia status `withdrawn`, ale zespół widzi je wyłącznie przez
  `GET /admin/profiles?status=withdrawn`, bez `Notify::send`/`AuditLog::record` z
  dedykowanym typem. Po przyznaniu — jedno dopisane wywołanie każdego, bez zmian
  kształtu API.
- **Drugi seeder do testu równoległych decyzji administracji** — zgłoszenie do
  strażnika schematu (tasks.md 9.3): obecny stan `ola@demo.pl` wystarcza jako demo
  ★1/★2; test współbieżności dwóch decyzji na różnych wnioskach nie jest częścią
  kryteriów akceptacji tego pakietu.
