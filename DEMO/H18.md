## Zakres (z `01-pakiety-zadan.md`)

„Na czym stoi każda osoba" w jednym miejscu: lista kont z filtrem roli i
wyszukiwarką, karta osoby (profil, postępy z `ProgressAggregator`, dokumenty,
ostatnie powiadomienia, wpisy audytu), konta (tworzenie z zaproszeniem, edycja
z e-mailem, z audytem), blokada z powodem, eksport CSV wspólnym helperem.

## Co działa

**Backend — `routes/api/h18.php` (flaga `features.h18`), pod `auth:sanctum` +
`role:project_manager,super_admin`:**

| Metoda | Trasa | Zachowanie |
|---|---|---|
| `GET` | `/api/v1/admin/users` | paginowana lista; filtry `role`, `status`, `search` (imię/nazwisko/e-mail, `ilike`), `sort` (domyślnie `-created_at`); koperta `{data, meta}` |
| `GET` | `/api/v1/admin/users/export.csv` | `text/csv; charset=utf-8` + BOM + `;` przez `Csv::download`; te same filtry co lista |
| `GET` | `/api/v1/admin/users/{id}` | karta w kopercie: `profile` (jak `/me`, pełny PESEL), `progress` (5 kluczy z `ProgressAggregator::for`), `documents` `{id,type,number}`, `recent_notifications`, `audit_entries` (podmiot = ta osoba); nieznane `id` → 404 |
| `POST` | `/api/v1/admin/users` | konto `status=active`, bez hasła, `activation_token`; rekord `emails` `status=simulated` z linkiem `auth/activate`; audyt `user.created`; duplikat e-maila → 409 `email_already_registered` z `reason.existing_user_id` |
| `PATCH` | `/api/v1/admin/users/{id}` | edycja pól konta (w tym `email`, unikalny); audyt `user.updated` z listą `changed`; nieznane `id` → 404 |
| `POST` | `/api/v1/admin/users/{id}/block` | `reason` wymagany; `status=blocked`; audyt `user.blocked` z powodem |

- **Matryca ról** (`AdminUserController::assertMayAssignRole`) — `project_manager`
  nie utworzy ani nie nada roli `super_admin` i nie zmienia (ani nie blokuje)
  kont, które już ją mają → 403 `forbidden` **przed** zapisem i audytem
  (audyt nie rośnie). `super_admin` przechodzi.
- **Wspólne zapytanie** `App\Queries\AdminUserQuery` zasila listę i CSV — wynik
  obu tras zawęża się identycznie.
- **Postępy karty** pochodzą wyłącznie z `ProgressAggregator::for` (to samo
  źródło co pulpit H19 i raport H20) — bez własnych zliczeń.
- **Komunikat logowania** — obsługa `status = blocked` istnieje już w starterze
  (`AuthController::login` → 403 `forbidden`, „Konto zostało zablokowane…"),
  odrębna od `access_expired` z `EnsureAccessActive` (H04). Pakiet dodał test
  rozróżnienia, nie zmieniał kodu logowania.

**Frontend — `#/admin/uczestniczki` + karta:**

- `/admin/uczestniczki` (`app/(administracja)/admin/uczestniczki/page.tsx` →
  `components/h18/AdminUsersList.tsx`) — tabela (`components/ui/Table`), filtr
  roli (`Select`), wyszukiwarka (`Input`), paginacja, przycisk „Eksport CSV"
  (`downloadFile` z Bearerem), stany pusty i błędu.
- `/admin/uczestniczki/[id]` (`app/(administracja)/admin/uczestniczki/[id]/page.tsx`
  → `components/h18/AdminUserCard.tsx`) — pięć sekcji karty, formularz edycji
  konta (błędy 422 mapowane na pola), akcja blokady z polem powodu; stan
  „nie znaleziono" (404) i błąd.
- Wpis menu „Uczestniczki" w `lib/menu/admin/{h18-uczestniczki.ts,index.ts}`
  (plik H18-owned, samo-rejestrujący się).

## Jak pokazać (scenariusz ręczny)

Wymagane: `docker compose up -d --wait`, `cd frontend && npm run dev`.

1. **Logowanie** — http://localhost:3000/logowanie → `admin@demo.pl` / `admin1234`
   (albo `opiekun@demo.pl` / `admin1234`, rola `project_manager`).
2. **Lista** (`/admin/uczestniczki`) — wybierz rolę „Wolontariusz" + wpisz
   `demo` → **Filtruj**: lista zawęża się do wolontariuszek (`marta@demo.pl`,
   `ola@demo.pl`), bez opiekunki i admina.
3. **Eksport CSV** — kliknij „Eksport CSV" → plik `osoby.csv` z BOM i `;`,
   otwiera się w Excelu, zawiera tylko przefiltrowane wiersze.
4. **Karta osoby** — kliknij „Marta Demo" → sekcja „Postępy": etapy `1 / 10`,
   godziny stażu `41.5`, obecności `5`, warsztat `NIE`. PESEL widoczny w całości.
   Sekcje „Dokumenty" (porozumienie wolontariackie), „Ostatnie powiadomienia"
   (nieprzeczytane `internship.returned`), „Wpisy audytu".
5. **Matryca ról** — jako `opiekun@demo.pl` otwórz kartę dowolnej osoby, w
   „Edycja konta" ustaw rolę „Super Admin" → **Zapisz** → błąd 403
   „Tylko Super Admin może zarządzać kontami Super Admina."
6. **Blokada** — w „Blokada konta" wpisz powód → **Zablokuj konto**. Wyloguj się,
   spróbuj zalogować jako zablokowana osoba → komunikat o blokadzie
   („Konto zostało zablokowane…"), nie o wygaśnięciu dostępu.

> Krok „pełne ręczne przejście w przeglądarce (w tym przegląd klawiaturą obu
> ekranów)" **nie został wykonany w tej sesji** — backend potwierdzony testami,
> frontend potwierdzony `npm run lint` + `npm run build`, ale nie klikany ręcznie.

## Czego brakuje / świadome decyzje

- **Typ powiadomienia dla zaproszenia z `POST /admin/users`** — rejestr §3.1 go
  nie ma. Pakiet zapisuje rekord `emails` o statusie `simulated` bezpośrednio
  (bez „dzwonka"). **Do potwierdzenia u strażnika kontraktu** — jeśli slug
  powstanie, podmiana na `Notify::send` bez zmiany trasy ani odpowiedzi
  (design.md D5). Zgłoszenie: _(do wysłania)_.
- **`PUT /admin/users/{id}/supervisor`** (przypisanie superwizora) — poza
  zakresem H18, blokuje H12 (wspólny właściciel endpointu). Karta nie pokazuje
  superwizora.
- **`sensitive.viewed` przy otwarciu karty** — §3.2 wiąże ten slug z H03/H15,
  nie z H18. Karta go nie emituje.
- **Pełna matryca uprawnień per rola per akcja** — zaimplementowana tylko reguła
  z kryterium 2★ (ochrona `super_admin`). Reszta po hackathonie.
- **`search`** działa po `first_name`/`last_name`/`email` (kolumny jawne) — po
  polach szyfrowanych aplikacyjnie (`pesel`, adres) nie da się filtrować w SQL.
- **Odblokowanie / usuwanie kont / reset dostępu** — brak tras w kontrakcie,
  poza zakresem.
- **Board / PR / claim na `origin/main`** — do zrobienia poza tą sesją:
  ustawienie właściciela `Tomek` i statusu `W TOKU` we wpisie 3.8
  `openspec/changes/koordynacja-pakietow-h01-h21/tasks.md` na `origin/main`,
  potem PR z gałęzi `pakiet/H18-panel-osob-i-karta-osoby`.
